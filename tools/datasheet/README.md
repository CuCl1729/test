# ゲームデータのスプレッドシート

Googleスプレッドシートに書いたゲームデータから、`.mcfunction`((と鉱脈の鉱石ブロックのルートテーブル))を自動で作ります。
対象は、武器・防具・アクセサリー・シリーズ・レシピ・ルーン・消耗品・素材・敵・職業・ステータスの表・魔法とバフの数値・初期値・定数・原石・鉱山・鉱脈・ツルハシです。
生成されたファイルは1行目に「自動生成」と書いてあります。直接は編集せず、スプレッドシートを直して作り直してください。

## 最初の準備(1回だけ)

1. Googleスプレッドシートを新しく作り、`data/` にある23個のCSVを取り込む
   (「ファイル → インポート → アップロード」で1つずつ選び、「新しいシートを挿入する」)。
   タブ名は何でもかまいません(下の表の名前にしておくと分かりやすいです)
2. 「共有」から「リンクを知っている全員」を「閲覧者」にする(スクリプトがログインなしで読めるようにするため)
3. `config.example.json` をコピーして `config.json` を作り、書く(`config.json` はシートの場所が分かってしまうので、gitの管理から外してある)
   - `sheet_id`: スプレッドシートのURLの `/d/` と `/edit` の間の文字列
   - `tabs` の各値: そのタブを開いたときのURLの末尾 `#gid=` の数字

| config.jsonのキー | 内容 | CSV |
|---|---|---|
| `stats` | ステータス | `data/stats.csv` |
| `materials` | 素材 | `data/materials.csv` |
| `weapons` | 武器 | `data/weapons.csv` |
| `forge_recipes` | 鍛冶場レシピ | `data/forge_recipes.csv` |
| `equipment` | 防具・アクセサリー | `data/equipment.csv` |
| `sets` | シリーズ | `data/sets.csv` |
| `set_effects` | 4部位効果 | `data/set_effects.csv` |
| `workshop_recipes` | 防具工房レシピ | `data/workshop_recipes.csv` |
| `runes` | ルーン | `data/runes.csv` |
| `consumables` | 消耗品 | `data/consumables.csv` |
| `enemies` | 敵 | `data/enemies.csv` |
| `enemy_gimmicks` | 敵のギミック | `data/enemy_gimmicks.csv` |
| `enemy_drops` | 敵のドロップ | `data/enemy_drops.csv` |
| `jobs` | 職業 | `data/jobs.csv` |
| `job_skills` | 職業スキル | `data/job_skills.csv` |
| `magic_values` | 魔法の数値 | `data/magic_values.csv` |
| `buff_values` | バフの数値 | `data/buff_values.csv` |
| `player_base` | プレイヤー初期値 | `data/player_base.csv` |
| `config` | 定数 | `data/config.csv` |
| `ores` | 原石 | `data/ores.csv` |
| `mines` | 鉱山 | `data/mines.csv` |
| `veins` | 鉱脈 | `data/veins.csv` |
| `pickaxes` | ツルハシ | `data/pickaxes.csv` |

`config.json` に gid が書いていないタブは、取得を飛ばして手元の `data/<キー>.csv` を使います(黄色で知らせます)。
タブを少しずつシートに移していけます。

## 使い方

1. スプレッドシートを編集する
2. `generate.cmd` をダブルクリックする(取得 → 検証 → 生成)
3. ゲーム内で `/reload` する

`generate.cmd -Offline` で実行すると、取得せずに `data/*.csv` から作ります。取得したCSVは `data/` に保存されるので、
コミットすればデータの変更がgitの差分で見られます。

書き方に誤りがあると、どのタブの何行目かを表示して、ファイルを1つも書き換えずに終わります。

## 数値の単位

- **ステータスの値は、ゲーム内の表示(装備の説明文)と同じ単位で書きます。** スクリプトが内部の値(×100)に直します。
  - 敵の HP・MP・攻撃・防御・防御係数・会心率・会心ダメージ、職業の成長、バフの効果量、プレイヤー初期値が対象です
  - 小数第2位まで書けます(例: 防御の成長 `0.05`)
- 耐性(%)・経験値・確率(%)・回数・秒数などは、書いた値のままです
- 魔法の `params` だけは、関数に渡す値そのまま(内部の値)です(例: 火炎の `base=1000` は表示の10)

## 列の書き方

見出し(1行目)の文字で列を探すので、列の順番は自由です。空欄は「無し」の意味です。

- **ステータスの種類**(基礎ステ・ボーナス・メイン・2部位ボーナス・ルーンの能力)は `atk_add` / `def_m` / `hp_max_m` / `fire_resist_add` などです。
  使えるのは「ステータス」タブで「成長」があるものです。`_add` は実数、`_m` は%です
- **武器の属性の列**(物理・火・水・木・金・土): ダメージ式を `atk=200, base=200` の形で書きます。
  `atk`/`hp_max`/`def` は攻撃力・HP・防御力の何%か、`base` は固定値です
- **鍛冶場レシピ**: 素材は「素材」タブで種類が `素材` のもの、触媒は種類が `触媒` のもの(触媒なしは `none`)
- **防具工房レシピ**: 素材は「素材」タブで種類が `素材` のもの
- **防具の部位**: `head` / `chest` / `legs` / `feet` / `accessory`。アクセサリーはインベントリに入れておくだけで効きます
- **防具の色**: `#RRGGBB`(革防具の染め色)
- **シリーズの2部位ボーナス**: `def_m=5; hp_max_add=30` のように `;` で区切ります
- **4部位効果**(1つのシリーズに何行でも書けます)
  - `event`: いつ動くか(`magic_cast` 魔法を唱えたとき / `attack_hit` 攻撃が当たったとき / `damaged` ダメージを受けたとき)
  - `kind`: 何をするか。`data/test/function/equip/effect/<kind>.mcfunction` があるもの
    (`apply_buff` 相手にバフ付与 / `self_buff` 自分にバフ付与 / `magic_damage_up` 魔法ダメージ上昇)
  - `params`: その効果に渡す値。`id=poison; stacks=1; chance=20` のように書きます。
    数字は数値として、それ以外は文字列として渡されます。必要な値が足りなければ検証で知らせます
  - `説明`: 装備の説明文に出す文
- **新しい効果を作るとき**は、`equip/effect/<kind>.mcfunction` を1つ書いてから、`kind` にその名前を書きます

### ステータス(列: `種類` / `アイコン` / `名前` / `色` / `単位` / `抽選値` / `武器` / `成長`)

サブステータスの抽選表・レベルアップの伸び・説明文の表示を1行ずつ書きます。

- **抽選値**: サブステータスとして付くときの値。空ならサブステータスの抽選に出ません
- **武器**: `1` なら武器でも抽選に出ます。空なら防具・アクセサリーだけ(耐性など)
- **成長**: レベルアップ1回ぶんの伸び。空の種類は、装備のステータスとして使えません
- **単位**: 説明文で値の後ろに付ける文字(`%` か空)

### 素材(列: `id` / `元アイテム` / `名前` / `種類` / `部位`)

- **種類**: `素材`(鍛冶場・工房の材料) / `触媒` / `特殊` / `型紙`
  - `特殊` は鍛冶場で効果を足す素材です。効果はコード(`craft/weapon/forge/craft`・`asset/weapon/`)にあるので、
    新しく足すときはコードも要ります
- **部位**: 型紙のときだけ(`head` / `chest` / `legs` / `feet` / `accessory`)
- 敵のドロップ・デバッグの [素材全種] も、この定義からアイテムを作ります

### 敵(列: `id` / `名前` / `色` / `HP` / `MP` / `攻撃` / `防御` / `防御係数` / `会心率` / `会心ダメージ` / `経験値` / `攻撃属性` / `物理耐性`〜`土耐性` / `フィールドAI` / `防御の重み` / `命中時バフ` / `装備ドロップ`)

- **名前・色**: 頭上の名前。空なら名前を出しません
- **HP〜会心ダメージ**: 表示の単位(防御が防御係数と同じとき、受けるダメージが半分)。HP以外は空なら0
- **攻撃属性**: 通常攻撃の属性。`物理` / `火` / `水` / `木` / `金` / `土`(空なら物理)。受ける側のその属性の耐性で減ります
- **耐性**: %(100で効かない)
- **フィールドAI**: `1` ならフィールドを歩き回り、近づくと戦闘を仕掛けてきます
- **防御の重み**: ターン制で防御を選ぶ重み(攻撃は60)。空なら防御しません
- **命中時バフ**: 攻撃を当てたときに付けるバフ。`poison 1 50; …`(バフのid 段数 確率%。確率を省くと必ず)
- **装備ドロップ**: `goblin_helmet=5; …`(防具のid=確率%)

### 敵のギミック(列: `敵` / `id` / `重み` / `HP以下` / `クールダウン` / `params`)

ターン制で敵が選ぶ特別な行動です。`id` は `battle/enemy_ai/gimmick/<id>.mcfunction` があるもの。
**HP以下**は、HPが何%以下のときだけ選ぶか(空なら100 = いつでも)。**クールダウン**は使った後に選ばないターン数です。
**params** はそのギミックに渡す値で、関数の `$(…)` がすべて要ります(書いた値のまま渡します)。

| id | 内容 | params |
|---|---|---|
| `enrage` | 自分にバフを付けてから通常攻撃 | `buff=atk_up; stacks=2` |
| `magic` | 魔法で攻撃(攻撃力×power%、会心なし) | `element=fire; power=150; target=one; label=火の玉` |
| `heal` | 自分のHPを回復 | `percent=20`(最大HPの%) |
| `curse` | プレイヤーにバフ(デバフ)を付ける | `buff=poison; stacks=1; chance=100; target=all` |
| `rally` | 同じ戦闘の敵全員にバフを付ける | `buff=atk_up; stacks=1` |

- `buff` は `init/asset/buff/buffs` のバフ、`element` は `physics` / `fire` / `water` / `wood` / `metal` / `earth`、
  `target` は `one`(一番近い1人)か `all`(全員)です。`chance` は付く確率(%)です

### 敵のドロップ(列: `敵` / `素材` / `最小` / `最大`)

倒したときに落とす素材。敵の定義の `material_drops` に入ります。
倒すと1行ごとに `最小`〜`最大` 個を抽選し(同じ素材の行が2つあれば2回抽選して足します)、報酬を受け取る全員に同じ種類・同じ個数が入ります。
抽選は `test:rng/roll`(キー `material_drop`)を通るので、デバッグメニューで固定できます。

### 職業(列: `id` / `名前` / `色` / `前提` / `経験値係数` / `成長`)

- **前提**: 解放の条件。`warrior=5; …`(職業のid=レベル)
- **経験値係数**: 次のレベルまでの経験値 = レベル² × 係数(1以上)
- **成長**: 1レベルごとの伸び。`atk=2; def=0.05`(表示の単位)。使えるのは `atk` / `def` / `hp_max` / `mp_max` / `crit_rate` /
  `crit_damage` / `effect_damage` / `magic_efficiency` / `divergence` / `hp_regene` / `mp_regene`
- 並び順がJobステーションの表示順です(7つずつページを送って表示)

### 職業スキル(列: `職業` / `id` / `名前` / `必要レベル` / `前提スキル` / `コスト` / `種類` / `params`)

- **前提スキル**: 先に覚えるスキル。同じ職業のスキルのidを `;` で区切ります
- **コスト**: 覚えるのに使うスキルポイント
- **種類**: `job/skill/handler/<種類>.mcfunction` があるもの(`damage_cone` 扇状の範囲攻撃 / `self_buff` 自分にバフ /
  `revive` 倒れた味方を1人起こす)。ターン制で使うには `battle/action/job_skill/handler/<種類>.mcfunction` も要ります
- **params**: その種類に渡す値(例: `angle=60; multiplier=150; mp_cost=10; reach=5`。
  `revive` は `mp_cost=30; percent=30; radius=8` = 消費MP・戻すHP(最大HPの%)・リアルタイムで届く距離)
- 1つの職業にいくつでも書けます(Jobステーションでは7つずつページを送って表示)。並び順が表示順です

### 魔法の数値(列: `要素` / `コスト` / `params`)

魔法の要素(タイプと効果)ごとの消費MPと数値です。要素の一覧(名前・アイコン・組み合わせの規則)は
`init/asset/magic/types`・`effects` に手で書いてあり、ここではすべての要素に行が要ります。
`params` は要素の関数(`asset/magic/<type|effect|status>/<要素>.mcfunction`)の `$(…)` で、内部の値で書きます
(例: 投射 `speed=100; range=20`、威力上昇 `per_stack=1000; max_stacks=3`)。

### バフの数値(列: `バフ` / `時間` / `最大段数` / `間隔` / `params`)

- **時間**: 続く秒数(ターン制では10秒で1ターン)
- **間隔**: 一定時間ごとに効くバフ(毒など)の間隔(秒)。そういうバフでは必須
- **params**: 効果の関数(`buff/on/<event>/<バフ>.mcfunction`)の `$(…)`。表示の単位で書きます(例: 攻撃力上昇 `per_stack=5`)
- バフの一覧(名前・色・アイコン・重ね方)は `init/asset/buff/buffs` に手で書いてあり、ここではすべてのバフに行が要ります

### プレイヤー初期値(列: `ステータス` / `値`)

初めて入ったときの能力値(表示の単位)。すべてのステータスに行が要ります。`/reload` すると、今いるプレイヤーにも入れ直します。

### 定数(列: `キー` / `値` / `説明`)

キーは決まっていて、すべて必須です。

| キー | 意味 |
|---|---|
| `turn_time` | 手番の制限時間(秒) |
| `turn_warn` | 自動で防御する前に予告を出す残り時間(秒) |
| `enemy_delay` | 敵が行動を選ぶまでの間(tick。20で1秒) |
| `accessory_limit` | インベントリに入れておくと効くアクセサリーの数 |

### ルーン(列: `id` / `元アイテム` / `名前` / `能力`)

強化台(付与モード)で装備の自動発動の枠に入れると、常に能力が上がります(入れたルーンは消費します)。

- **能力**: `atk_m=5; def_add=20` のように `;` で区切ります。ステータスの種類は上の「ステータスの種類」と同じです
- 枠には付けた時点の能力が写されるので、後で能力を変えても、付与済みの装備は変わりません

### 消耗品(列: `id` / `元アイテム` / `名前` / `every` / `効果` / `params`)

強化台(付与モード)で装備の自動発動の枠に設定すると、その枠のイベントが `every` 回起きるごとに、持ち物から1個使います
(強化台に置いた消耗品は減りません。持っていなければ何もしません)。

- **every**: 1以上の整数。イベントが何回起きるごとに1個使うか
- **効果**: `data/test/function/consumable/effect/<効果>.mcfunction` があるもの(説明文用の `consumable/lore/<効果>.mcfunction` も要ります)
  - `heal_hp` HPを回復 / `heal_mp` MPを回復: `params` は `percent=20; flat=10`
    - `percent` は最大値の何%か、`flat` は固定の量(装備の説明文と同じ単位。30なら「HP +30」と同じ量)
    - 両方書くと足した分だけ回復します。片方だけでもよく、無い方は0になります。どちらも0以上の整数で、どちらかは1以上にします
  - `self_buff` 自分にバフを付ける: `params` は `id=atk_up; stacks=1`(`id` は `init/asset/buff/buffs` のバフ)
  - `revive` 倒れた味方を1人起こす: `params` は `percent=30; radius=8`
    - `percent` は戻すHP(最大HPの%。1〜100の整数)、`radius` はリアルタイムで届く距離(ブロック)
    - ターン制では、アイテムの行動で使うと同じ戦闘で倒れている味方を起こします。起こす相手がいなければ使いません
- **新しい効果を作るとき**は、`consumable/effect/<効果>.mcfunction` と `consumable/lore/<効果>.mcfunction` を書いてから、`効果` にその名前を書きます。
  回復量などの数値は関数に書かず、`params` で渡してください

### 原石(列: `id` / `名前` / `アイテム`)

鉱山で掘ると手に入る原石の種類です。原石のアイテムは種類とレア度(1〜5)だけを持ち、同じ種類・同じレア度なら重なります。
レア度は名前の色で分かります(1 白 / 2 緑 / 3 青緑 / 4 紫 / 5 金)。

- **アイテム**: 見た目に使うバニラのアイテム(例: `raw_copper`)

### 鉱山(列: `id` / `名前` / `範囲` / `入口` / `リセット間隔`)

鉱山は場所です。中で何が掘れるかは、範囲の中に置いた「鉱脈のアマスタ」で決まります(下の「鉱脈」を参照)。

- **範囲**: 鉱山の範囲の2つの角(例: `100 30 200 140 70 240`)。この直方体の中にいる人を「鉱山の中にいる」とみなします。
  この中にある鉱脈のアマスタが、この鉱山の鉱脈になります
- **入口**: リセットしたときに、埋まってしまった人を移す座標(例: `98 40 220`)
- **リセット間隔**: 前回のリセットから、次にリセットできるまでの秒数。0ならいつでもリセットできます

鉱山は、`test:action` と `test:turn` の**同じ座標に同じ形で**作ります(状態はマップごとに別)。
誰もいない鉱山に最初の1人が入ったときに、範囲の中の鉱脈のアマスタが、それぞれの鉱脈を置き直します。
範囲の入口側の端には、鉱脈を置かないでください(リセットした瞬間に、入ってきた人が埋まらないようにするため)。

### 鉱脈(列: `id` / `鉱石ブロック` / `原石` / `必要ランク` / `レア度の重み` / `構造物`)

掘れる鉱石の種類です。どの鉱山にでも、いくつでも置けます(鉱山が増えても使い回せます)。

- **鉱石ブロック**: この鉱脈だけで使うバニラの鉱石ブロック(例: `deepslate_copper_ore`)。1つのブロックは1つの鉱脈だけに使えます
  - このブロックのルートテーブル(`data/minecraft/loot_table/blocks/<ブロック>.json`)を上書きして、掘ると「目印」が1個落ちるようにします。
    目印は持ち物に入るとすぐ原石に変わります
  - **ルートテーブルはマップ全体のそのブロックに効きます。鉱脈の鉱石ブロックを、鉱山の外の飾りなどに使わないでください**
  - JSONには自動生成の見出しを書けないので、古いルートテーブルは自動で消えません。
    **鉱脈を消したり鉱石ブロックを変えたりしたときは、古い `data/minecraft/loot_table/blocks/<ブロック>.json` を手で消してください**
    (生成の最後に、今回書き出したルートテーブルの一覧を表示します)。`red_shulker_box.json` は別の仕組みで使っているので消さないでください
- **原石**: 掘ると出る原石(「原石」タブの `id`)
- **必要ランク**: このブロックを掘れるツルハシのランク(この値以上)。どのツルハシでも掘れない鉱脈は、警告を出します(生成は止めません)
- **レア度の重み**: `1=60; 2=25; 3=10; 4=4; 5=1`(レア度=重み)。重みの合計に対する割合で、そのレア度の原石が出ます
- **構造物**: 鉱脈の形(鉱石の塊)の構造物(例: `test:vein/copper_vein`。ファイルは `data/test/structure/vein/copper_vein.nbt`)
  - ストラクチャーブロックで保存するときは、**鉱石以外の場所をストラクチャーヴォイドにしてください**。
    そうすると、置き直しても周りの通路や壁を上書きしません

**鉱脈の置き方**: デバッグメニューの「採掘」の欄で、鉱脈の `[<id>] 足元に設置` を押すと、足元のブロックの角に鉱脈のアマスタが置かれます。
アマスタの位置が、構造物を置く角(保存したときのストラクチャーブロックの範囲の角)になります。
アマスタは今いるマップだけに置かれるので、`test:action` と `test:turn` の両方で、同じ位置に置いてください。
[鉱脈の名前を表示] で、置いたアマスタの名前が見えます。[近くの鉱脈を消す] で、2ブロック以内のアマスタを消せます。

### ツルハシ(列: `id` / `名前` / `アイテム` / `ランク` / `採掘速度`)

- **アイテム**: 元にするバニラのツルハシ(例: `iron_pickaxe`)。見た目だけで、掘れるブロックや落ちる物はランクで決まります
- **ランク**: 1以上の整数。必要ランクがこの値以下の鉱脈の鉱石ブロックだけ壊せます(アドベンチャーモードの `can_break`)。
  掘れる鉱脈が1つも無いツルハシは誤りになります
- **採掘速度**: 掘れる鉱石を掘るときの速さ(0より大きい数)
- 耐久値は減りません
